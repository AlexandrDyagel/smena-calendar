# Календарь сменных графиков

Одностраничное приложение для планирования посменной работы: произвольные **циклические шаблоны**
графиков (в том числе «2 через 2», «сутки через трое», «день через день», «5/2» и любые
пользовательские последовательности), назначение шаблонов сотрудникам с определённой даты,
ручные переопределения отдельных дней, отчёты по сменам и часам, экспорт в CSV / JSON / iCal.

Приложение полностью работает в браузере: бэкенда, базы данных и авторизации нет,
все данные хранятся в `localStorage`.

## Стек

| Технология | Версия | Зачем |
| --- | --- | --- |
| Vue 3 | 3.5+ | Composition API, `<script setup lang="ts">` |
| TypeScript | 5.9 | строгая типизация доменных моделей |
| Vite | 7 | сборка и dev-сервер |
| Tailwind CSS | 4 (`@tailwindcss/vite`) | стили, тёмная тема через класс `.dark` |
| Pinia | 3 | 5 независимых сторов + автосохранение |
| vue-router | 4 | hash-маршрутизация (работает на любом статическом хостинге) |
| dayjs | 1.11 | локализация дат (`ru`), форматирование |

### Почему dayjs, а не date-fns

1. **Размер**: ~7 КБ gzip против ~30+ КБ у date-fns даже с tree-shaking.
2. **Локаль из коробки**: `import 'dayjs/locale/ru'` — один импорт; у date-fns локаль
   подключается на каждую функцию и легко забывается.
3. **Мутабельность/иммутабельность**: dayjs-объекты иммутабельны и легковесны, при этом
   API привычен.
4. **Арифметика дат в этом проекте не зависит от библиотеки**: расчёт цикла идёт через
   порядковый номер суток (`Date.UTC(...)/86400000`), поэтому переходы на летнее время
   и UTC-смещения не влияют на результат. dayjs используется только для форматирования
   и локализации.

```bash
# 1. установка зависимостей
npm install

# 2. запуск dev-сервера (http://localhost:5173)
npm run dev

# 3. проверка типов + production-сборка
npm run build

# 4. локальный просмотр собранного приложения

```

Дополнительные команды:

```bash
npm run typecheck    # только проверка типов (vue-tsc --noEmit)
npm run build:only   # сборка без проверки типов
npm run check:logic  # самопроверка расчёта смен, отчётов и экспорта (без браузера)
npm run check:ui     # отрисовка всех экранов через SSR + проверка сохранения
npm run check:dom    # клики в реальном DOM (jsdom): выбор сотрудника, модальные окна
npm run check        # всё вместе: типы + логика + отрисовка + взаимодействие
```

`check:logic`, `check:ui` и `check:dom` — это встроенные самопроверки (41, 51 и 60 assertions):
они прогоняют пресеты графиков, расчёт циклов, приоритет переопределений, отчёты, CSV/iCal,
рендерят все экраны, монтируют разделы в настоящий DOM, проверяют клики и содержимое
скачиваемых файлов, а также цикл «запись → чтение → очистка» для обоих хранилищ
(localStorage и нативного SharedPreferences).
`check:logic` требует Node 22.18+ (запуск TypeScript без сборки); `check:dom` использует jsdom.

Сборка под Android описана ниже в разделе «Версия для Android (Capacitor)».

При первом запуске автоматически загружаются демонстрационные данные: 6 шаблонов
(включая обязательные «2 через 2», «Сутки через трое», «День через день», «5/2» и сложный
8-дневный цикл «С В С В В В В В»), 6 сотрудников, назначения шаблонов и 4 ручных переопределения дня.
Демо-данные можно удалить на экране «Экспорт и импорт» → «Опасная зона».

## Версия для Android (Capacitor)

Приложение собирается в APK — тот же код, что и веб-версия, внутри нативного контейнера.

```bash
npm run android:sync     # сборка веб-части + копирование в android-проект
npm run android:open     # открыть проект в Android Studio
npm run android:apk      # выпустить отладочный APK (Windows)
npm run android:run      # собрать и запустить на подключённом устройстве/эмуляторе
npm run assets:generate  # перерисовать значок и заставку (см. ниже)
```

Для macOS/Linux последний шаг вручную:

```bash
npm run android:sync
cd android && ./gradlew assembleDebug
# APK: android/app/build/outputs/apk/debug/app-debug.apk
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

**Что нужно установить для сборки APK:** JDK 21 и Android SDK (проще всего —
Android Studio с SDK Platform 36 и Build-Tools). Настройки проекта:
`minSdkVersion 24` (Android 7.0), `compileSdk/targetSdk 36`, `applicationId ru.smena.calendar`.

### Хранение данных на телефоне

| Платформа | Хранилище | Почему так |
| --- | --- | --- |
| Android / iOS | **SharedPreferences** / UserDefaults через `@capacitor/preferences` | живёт в приватных данных приложения, не очищается системой при нехватке места |
| Браузер | `localStorage` | обычное веб-хранилище |
| Если хранилище недоступно | память процесса | приложение работает, но предупреждает об этом в шапке |

Ключевое отличие от веб-версии: во WebView Android `localStorage` может быть очищен
системой (как и любые данные сайта), поэтому на телефоне данные пишутся в нативное
хранилище. Выбор делается автоматически в `src/services/repository.ts`:

```ts
if (Capacitor.isNativePlatform()) return new PreferencesRepository()
return new LocalStorageRepository().isAvailable() ? new LocalStorageRepository() : new MemoryRepository()
```

Интерфейс `DataRepository` стал асинхронным (`load/save/clear` возвращают промисы),
поэтому загрузка данных выполняется **до монтирования** приложения в `src/main.ts`,
а автосохранение (`useAutoPersist`) дополнительно срабатывает, когда приложение
уходит в фон (`visibilitychange`) — система может закрыть WebView в любой момент.

### Экспорт файлов на телефоне

В WebView ссылка `<a download>` ничего не скачивает, поэтому CSV/JSON/iCal
сохраняются через `@capacitor/filesystem` в «Документы» приложения
(папка `smena-calendar`) и сразу предлагаются в системном окне «Поделиться» —
оттуда файл можно отправить в почту, мессенджер или сохранить в «Загрузки».
В браузере работает обычное скачивание. Логика — `src/services/file-export.ts`.

### Кнопка «Назад», строка состояния и вибрация

- **Системная кнопка «Назад»** (`src/services/back-button.ts`) работает по приоритету:
  закрывает верхнее открытое окно или панель → возвращает по истории маршрутов →
  выходит из приложения. Компоненты регистрируются сами через
  `useBackHandler(...)`: модальные окна, панель дня и мобильное меню. Порядок закрытия
  всегда обратный порядку открытия — обработчики снимаются при закрытии.
- **Строка состояния** (`useTheme`) меняет оформление вместе с темой приложения:
  светлые значки на тёмной теме и наоборот. На Android 15+ фон строки рисует система
  (edge-to-edge), поэтому изменение цвета фона не критично.
- **Вибрация** (`src/services/feedback.ts` на базе `@capacitor/haptics`): короткий отклик
  при сохранении и снятии переопределения дня, предупреждающий — при подтверждении
  опасных действий (удаление работника, шаблона, всех данных). В браузере вызовы
  игнорируются, поэтому код можно вызывать без проверок.

### Заставка: «дышащий» логотип с названием

Заставок две, и они работают вместе, без белой вспышки между ними:

1. **Нативная** (Android/iOS) — системная картинка из ресурсов, видна до загрузки WebView.
   В `capacitor.config.ts` она настроена как `launchAutoHide: false`: приложение само
   скрывает её через `@capacitor/splash-screen`, когда данные прочитаны и интерфейс смонтирован.
2. **Веб-заставка** — разметка и стили прямо в `index.html`, поэтому она видна мгновенно,
   ещё до загрузки бандла: логотип плавно «дышит» (`@keyframes app-splash-breathe`,
   масштаб 1 → 1.06 с лёгким затуханием), под ним название «Календарь смен»,
   подзаголовок и три пульсирующие точки.

Когда приложение готово, `hideSplash()` в `src/main.ts` убирает нативную заставку и
плавно растворяет веб-слой (`src/services/splash.ts`). Длительность затухания в CSS
и в коде синхронизирована — это проверяется автотестом, чтобы не появилось рывка.

Мелочи, которые уже учтены:

- при системной настройке **«уменьшить движение»** анимация отключается
  (`@media (prefers-reduced-motion: reduce)`);
- если бандл не загрузился, заставка всё равно исчезнет через 8 секунд — интерфейс
  не останется закрытым навсегда;
- фон заставки совпадает с нативной (фирменный синий), поэтому переход незаметен
  в обеих темах.

Текст на заставке набран системным шрифтом — веб-шрифты не подключаются, чтобы
не было подмены шрифта на первом кадре.

### Значок и заставка (ресурсы)

Исходники и готовые ресурсы Android генерируются одним скриптом — без графических
библиотек, своим кодировщиком PNG:

```bash
npm run assets:generate
```

Скрипт [`scripts/brand-assets.mjs`](scripts/brand-assets.mjs) рисует фирменный календарь
(цвета смен совпадают с цветами типов смен в приложении) и записывает:

- `assets/*.png` — исходники 1024×1024 и 2732×2732 для других платформ и для будущего
  использования (например, iOS через `@capacitor/assets`);
- `mipmap-{mdpi…xxxhdpi}/ic_launcher.png`, `ic_launcher_round.png` — обычный и круглый значки;
- `mipmap-{mdpi…xxxhdpi}/ic_launcher_foreground.png` — передний план адаптивного значка
  (мотив занимает центральные 62 %, то есть безопасную зону);
- `drawable*/splash.png` — заставки для портретной и альбомной ориентации всех плотностей;
- `values/ic_launcher_background.xml` и `values/colors.xml` — фирменные цвета
  (фон адаптивного значка, `colorPrimary`, `colorAccent`).

Заставка сделана в фирменном синем цвете с белым календарём, поэтому одинаково выглядит
в светлой и тёмной теме и не требует отдельного варианта `-night`.

### Что не входит в сборку

- `android/` — сгенерированный проект (Gradle + Java). Правки в нём перезаписываются

## Как работает расчёт смен

Вся логика вынесена в чистые функции `src/utils/schedule.ts` (без Vue, DOM и хранилища):

```ts
resolveEmployeeDay(employeeId, date, assignments, templates, overrides): CalendarCell
```

Порядок приоритетов:

1. **Ручное переопределение** дня — всегда побеждает шаблон.
2. **Действующее назначение шаблона**: если на дату активно несколько назначений,
   берётся последнее начавшееся (при равенстве дат — созданное позже); остальные
   попадают в `conflictAssignmentIds` и подсвечиваются в интерфейсе.
3. Если назначения нет — день считается **неразмеченным** (`source: 'none'`).

Позиция дня внутри цикла:

```
offset = dayIndex(date) - dayIndex(assignment.startDate)   // может быть отрицательным
index  = ((offset % cycleLength) + cycleLength) % cycleLength
```

Модуль от отрицательного числа берётся корректно, поэтому даты **раньше** даты начала шаблона
рассчитываются правильно (цикл продолжается «назад»). Порядковый номер суток считается от
`Date.UTC`, что исключает ошибки из-за часового пояса и перехода на летнее время.

## Хранение данных

- Ключ `smena-calendar:data` — конверт `{ version, savedAt, data }`.
- Ключ `smena-calendar:ui` — настройки интерфейса (тема, фильтры, режим просмотра).
  На Android они тоже попадают сюда (в localStorage WebView) — это некритичные данные,
  а тема дополнительно хранится в основном наборе и восстанавливается при запуске.
- `SCHEMA_VERSION` + реестр миграций в `services/migrations.ts`; при изменении структуры
  достаточно добавить шаг миграции.
- Импорт проходит через `sanitizeAppData`: некорректные записи отбрасываются
  с предупреждениями, а не ломают импорт целиком.
- Если постоянное хранилище недоступно (приватный режим браузера), приложение работает
  на хранилище в памяти и предупреждает об этом в шапке.
- Замена хранилища на IndexedDB или REST API — реализация интерфейса `DataRepository`
  в `services/repository.ts` (сторы и компоненты менять не нужно).

## Экспорт и импорт

| Формат | Что выгружается |
| --- | --- |
| JSON | полная конфигурация (шаблоны, работники, назначения, переопределения, настройки) |
| CSV | расписание «дата × сотрудник»: тип смены, часы, источник, шаблон, комментарий |
| CSV (отчёт) | сводка по сотрудникам + детализация «сотрудник × тип смены» |
| iCal (.ics) | рабочие смены как события календаря (можно включать нерабочие дни) |

Экспорт календаря учитывает текущий период и фильтры (сотрудники, отделы, типы смен).
CSV формируется с разделителем `;` и BOM — корректно открывается в русском Excel.

## Проверенные сценарии

- Шаблон «2 через 2» создаётся и назначается сотруднику.
- «Сутки через трое», «День через день», «5/2» доступны как пресеты.
- Произвольный цикл любой длины: элементы добавляются, удаляются, меняют порядок,
  задаются часы, подпись и комментарий; есть предпросмотр на 14/30/60 дней.
- Календарь месяца/недели/списка корректно показывает смены, выходные, праздники,
  сегодняшний день и ручные изменения.
- Переопределение дня меняет отображение и учитывается в отчётах и экспорте.
- Отчёт за месяц/квартал/год/произвольный период считает смены по типам и часы.
- Данные сохраняются после перезагрузки страницы.
